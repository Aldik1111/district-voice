# Голос района · А-7

Локальная платформа анализа обращений граждан Казахстана. **Этап 5: финальный аудит MVP и исправление ошибок.** Результаты проверок и оставшиеся ограничения — [docs/QA_REPORT.md](docs/QA_REPORT.md). Сценарий на 3–5 минут — [docs/DEMO.md](docs/DEMO.md), реализация MVP — [docs/MVP-COMPLETION.md](docs/MVP-COMPLETION.md).

Проект целиком ведёт один владелец. Старое распределение в `participants/` отменено; инструкции сохранены как исторические требования к модулям.

## Что работает

- Единый адаптивный Next.js интерфейс: обзор с графиками и фактическими счётчиками, загрузка данных, все обращения, AI-анализ, системные проблемы и отчёты. Белые карточки, светлая тема, синие акценты, Recharts и Lucide.
- FastAPI + SQLAlchemy + локальная SQLite; обращения, результаты анализа и ручные решения сохраняются между запусками.
- CSV (UTF-8/BOM, Windows-1251) и первый лист XLSX; сопоставление столбцов, предпросмотр маскированных строк, ошибки с номерами строк, подтверждение импорта.
- Обязательные поля: источник, ID в источнике, дата, текст. Адрес и исходный статус необязательны; пропуски явно обозначаются. Даты: ГГГГ-ММ-ДД, ДД.ММ.ГГГГ, ДД/ММ/ГГГГ, ГГГГ/ММ/ДД или ISO datetime.
- Защита по паре `источник + ID`: повтор той же записи не увеличивает статистику, конфликт содержимого не перезаписывает запись. Повтор подтверждения одной партии безопасен.
- Локальное маскирование телефонов, email и 12-значных ИИН/ЖСН, эвристики имён, документов и квартир; сомнительные записи требуют проверки. Сырые оригинальные файлы и тексты не сохраняются. Это **не гарантия полного обезличивания**.
- Ручная правка безопасного текста/адреса с повторной проверкой и защитой от перезаписи устаревшей версии. Поиск, фильтр проверки, пагинация и показатели по источникам, датам и адресам.
- Классификация русских и казахских обращений, нормализация известных вариантов адресов, объяснения и признаки неопределённости. Для локальных embeddings предусмотрена Multilingual E5; при её недоступности используется TF-IDF со словарными правилами.
- Предложение локальных случаев и повторяющихся проблем с учётом темы, места и времени. Карточки содержат реальные ID, тексты, даты, источники, основания и ограничения объединения.
- Подтверждение, отклонение и возврат группы на проверку с основанием, версией и историей. Исторические и устаревшие группы защищены от изменения статуса. Новый анализ создаёт новые предложения и не переносит ручные решения автоматически.
- Ручное добавление/исключение обращений, разделение/объединение групп, название и категория группы. Связи и показатели пересчитываются, старое основание AI помечается устаревшим, история показывает значения до/после и явного демо-оператора.
- Сводки по периоду и территории: черновик, правка текста, утверждение неизменяемого снимка SQLite, новые версии, CSV и XLSX. Рабочие JSON-снимки запуска и печать сохранены отдельно.
- Набор из 180 синтетических RU/KK строк и независимый эталон `data/demo-180-gold.json`. Кнопка «Загрузить демоданные» использует существующий импорт с валидацией.
- История запусков, безопасные сообщения об ошибках, повторный анализ и ручная коррекция категории. Правка категории требует пересчёта групп; исторические результаты не подменяются новыми.

Оценка метода не является вероятностью правильного ответа. Предполагаемые перепубликации не считаются подтверждённо независимыми свидетельствами; количество сообщений не равно числу жителей. Успешная загрузка и использование E5 подтверждаются **фактическим методом завершённого запуска**, а не наличием файлов модели. Подробности: [AI-движок](docs/AI-ENGINE.md).

## Требования

Windows 10/11, PowerShell, Git, **Node.js 22 или 24 LTS**, **Python 3.12**. Платные API, Docker и внешняя база не нужны. Базовый анализ работает с локальным scikit-learn; установка sentence-transformers и скачивание весов E5 необязательны.

Интернет нужен для первоначальной установки пакетов и отдельной загрузки модели, если выбран E5. Анализ использует локальные файлы и не отправляет обращения во внешние AI-сервисы.

Если `py` или `npm.cmd` не найдены, установите Python с python.org (с Python Launcher) и Node.js LTS с nodejs.org, затем откройте новый терминал. [Требования Next.js](https://nextjs.org/docs/app/getting-started/installation), [SQL в FastAPI](https://fastapi.tiangolo.com/tutorial/sql-databases/).

## Установка на Windows

Для первой установки нужны Python Launcher `py`, Node.js и Git. Клонируйте ветку MVP в выбранный рабочий каталог. Если репозиторий уже клонирован, откройте его корень и пропустите первые две команды. При наличии рабочего `backend\.venv` переходите к разделу «Запуск».

```powershell
git clone --branch feature/golos-rayona https://github.com/Aldik1111/district-voice.git
Set-Location .\district-voice
py -3.12 -m venv backend\.venv
.\backend\.venv\Scripts\python.exe -m pip install -r backend\requirements-lock.txt
npm.cmd --prefix frontend ci
```

Активация venv и изменение ExecutionPolicy не нужны. Не пересоздавайте работающий venv и не удаляйте базу ради запуска. Если Python Launcher отсутствует при первой установке, используйте полный путь к установленному `python.exe` вместо `py -3.12`. Чистая установка на новой машине в финальном аудите не проверялась.

### Необязательная локальная модель E5

Для резервного метода достаточно базовой установки. Для E5 выполните отдельно из корня репозитория:

```powershell
.\backend\.venv\Scripts\python.exe -m pip install -r backend\requirements-ai.txt
.\backend\.venv\Scripts\python.exe scripts\download_model.py
```

Загрузчик получает публичные файлы `intfloat/multilingual-e5-small` в `backend/models/multilingual-e5-small`, проверяет размер и доступные контрольные суммы и поддерживает повторный запуск после прерывания. Он не читает обращения из базы. После установки перезапустите backend. Другой путь задаётся через `DISTRICT_VOICE_MODEL_PATH`; точные команды, ревизия и ограничения модели — в [docs/AI-ENGINE.md](docs/AI-ENGINE.md).

Веб-приложение не скачивает модель автоматически. Режим `auto` пытается загрузить локальный E5 и при сбое переходит на TF-IDF, сохраняя причину. Режим `tfidf` принудительно выбирает резервный текстовый метод. Наличие файлов не означает, что модель успешно загружена или проверена на реальных данных.

## Запуск на Windows

Откройте два терминала в корне клонированного репозитория. В первом терминале:

```powershell
Set-Location .\backend
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --no-access-log
```

Во втором терминале — production-версия, использованная в финальном аудите:

```powershell
Set-Location .\frontend
npm.cmd run build
npm.cmd start
```

Откройте [http://127.0.0.1:3000](http://127.0.0.1:3000). [API-документация](http://127.0.0.1:8000/docs), [проверка сервера и базы](http://127.0.0.1:8000/api/health). Остановка — Ctrl+C в обоих терминалах. После успешной сборки для повторного запуска достаточно `npm.cmd start`. Перед новой сборкой остановите предыдущий frontend. Для разработки вместо build/start: `npm.cmd run dev`. Если npm установлен стандартно, но отсутствует в PATH, используйте `& 'C:\Program Files\nodejs\npm.cmd'` вместо `npm.cmd`. Также есть `scripts/start-backend.ps1` и `scripts/start-frontend.ps1` (последний запускает dev), если политика PowerShell разрешает локальные скрипты.

Проверка подключения из третьего терминала:

```powershell
Invoke-RestMethod 'http://127.0.0.1:8000/api/health'
Invoke-RestMethod 'http://127.0.0.1:3000/api/health'
```

В обоих ответах ожидаются `status: ok` и `database: ok`. Не запускайте второй экземпляр на уже занятом порту. После редактирования Python-файлов остановите и снова запустите backend: команда выше не использует autoreload.

Запускайте **один процесс/worker backend**. Расчёт выполняется синхронно и локально; второй анализ того же набора отклоняется, пока первый не завершён. Прерванный остановкой сервера запуск сохраняется как ошибка после перезапуска и допускает повтор.

Если порт занят, остановите свой прежний экземпляр. Для интерфейса используйте порт 3000; другой origin нужно явно добавить в конфигурацию backend. Для backend можно задать другой порт. При изменении порта backend задайте `$env:BACKEND_URL='http://127.0.0.1:8001'` **до запуска или сборки frontend**; по умолчанию используется 8000. Next.js проксирует `/api/*`, браузер обращается к тому же origin. Тайм-аут проксирования увеличен для локальных вычислений; процент готовности интерфейс не выдумывает.

## Проверка сценария

1. Откройте «Обзор», затем «Загрузка данных» → «Загрузить демоданные» либо выберите `data/demo-180.csv`.
2. Проверьте сопоставление, обезличенный предпросмотр и ошибки. На пустой базе: 180 строк → 176 добавлено, 2 отклонено, 2 технических дубля. При повторной загрузке: 0 добавлено, 2 отклонено, 178 дублей.
3. Подтвердите импорт, откройте реестр. Фильтры и поиск работают с сохранёнными записями. Небольшие файлы `data/demo/appeals-demo.csv` и `.xlsx` остаются отдельным тестом маскирования: 12 строк → 10 допустимых и 2 ошибки.
4. Перейдите в «AI-анализ», выберите автоматический режим, запустите или пересчитайте анализ. Смотрите **фактический метод выбранного завершённого запуска**, ошибки и неопределённости. При недоступном E5 приложение использует явно обозначенный TF-IDF.
5. Найдите группу водоснабжения на Абая, 150. Прочитайте подтверждающие сообщения и ID. Если в группе есть `SYN-021` о внутреннем ремонте крана, исключите его с комментарием. Обращение останется в реестре; счётчики и объяснение обновятся.
6. При необходимости измените название/категорию, добавьте, разделите или объедините записи. Проверьте историю и подтвердите группу. Обновите страницу: решение должно сохраниться.
7. В «Отчётах» выберите период и территорию → «Рассчитать показатели» → «Создать черновик». Отредактируйте текст и сохраните его.
8. Утвердите версию через диалог. Экспортируйте CSV или XLSX. Утверждённый снимок останется неизменным при последующих правках групп; для изменений создаётся новая версия.
9. Перезапустите backend и frontend: записи, решения и сводки остаются в SQLite. Новый анализ создаёт новые группы; прежние ручные решения хранятся в истории, но автоматически не переносятся.

## Проверки и сборка

Из корня репозитория, после остановки ранее запущенного frontend:

```powershell
Set-Location .\backend
.\.venv\Scripts\python.exe -m pytest -q
Set-Location ..\frontend
npm.cmd run build
npm.cmd run typecheck
npm.cmd run lint
```

Сборка первой создаёт типы Next.js, необходимые для `typecheck` после чистого клонирования. Тесты используют отдельные временные базы. Если окружение ограничивает запись в системный TEMP, добавьте `--basetemp` с **новой пустой папкой** внутри доступной рабочей директории; pytest очищает её при запуске. Фактические результаты — в [docs/QA_REPORT.md](docs/QA_REPORT.md).

Независимые синтетические контроли A–I через импорт, SQLite, реальную локальную модель, повтор анализа и перезапуск приложения (из корня репозитория):

```powershell
New-Item -ItemType Directory -Force work | Out-Null
.\backend\.venv\Scripts\python.exe scripts\qa_ai_controls.py --output work\qa-e5.json
.\backend\.venv\Scripts\python.exe scripts\qa_ai_controls.py --mode tfidf --output work\qa-tfidf.json
```

Первый контроль завершится с ошибкой, если E5 не запустится, даже когда резервный анализ успешно работает. Скрипт использует отдельные SQLite-файлы, запрещает внешние socket-соединения и сохраняет ожидаемые/полученные результаты. Это не оценка точности на реальном корпусе.

## Структура и данные

- `frontend/` — Next.js App Router, TypeScript, Tailwind CSS, Recharts, Lucide; страницы `/`, `/import`, `/appeals`, `/analysis`, `/problems`, `/problems/[id]`, `/reports`.
- `backend/app/` — FastAPI, SQLAlchemy, импорт, маскирование, API анализа и сохранение его результатов.
- `backend/app/ai/` — двуязычные правила, нормализация, локальные embeddings, TF-IDF и группировка.
- `backend/tests/` — проверки импорта, приватности, API, алгоритмов и согласованности снимков.
- `data/demo/`, `data/demo-180.csv`, `data/demo-180-gold.json` — только явно помеченные синтетические примеры и эталон.
- `scripts/` — запуск PowerShell и отдельная загрузка модели; `docs/` — требования, архитектура, AI-движок и статус.

SQLite создаётся в `backend/data/district_voice.db`. Переменная `DISTRICT_VOICE_DATABASE_URL` позволяет выбрать другую SQLite; родительская папка должна существовать. Этап 2 добавляет таблицы анализа, не изменяя схему и данные существующей таблицы обращений. При первом запуске новые таблицы создаются автоматически; удалять прежнюю базу не нужно.

База, виртуальная среда, `node_modules` и локальные веса модели исключены из Git. Основные зависимости закреплены в requirements и package.json; `npm ci` использует package-lock.json. `requirements-lock.txt` фиксирует базовую Python-среду вместе с scikit-learn, тестовыми и транзитивными зависимостями. `requirements-dev.txt` описывает прямые зависимости разработки; для воспроизводимой установки используйте lock-файл. Опциональная модель устанавливается отдельно через `requirements-ai.txt`.

## Приватность, ограничения и следующий этап

Это локальный прототип одного оператора: аутентификация, серверное разграничение ролей и доступ организаций пока отсутствуют. Запускайте на `127.0.0.1` и используйте демонстрационные данные. Публикация в сети и работа с реальными обращениями требуют отдельной защиты и проверки процедуры обезличивания.

Финальный online `npm audit` выявил 5 high-предупреждений в dev-цепочке ESLint/braces; production-аудит — 0 известных уязвимостей. Безопасной совместимой автоматической правки на момент проверки нет. Подробности, исправленные ошибки приложения и результаты NLP на большом эталоне приведены в [QA_REPORT.md](docs/QA_REPORT.md).

Лимиты импорта: 5 МБ, 5000 строк, 60 столбцов; XLSX без формул/макросов. Предпросмотр действителен 24 часа. **Один анализ поддерживает максимум 500 сохранённых обращений**; больший набор отклоняется целиком, без молчаливого усечения. Подозрительные записи не участвуют в embeddings и группировке, пока не пройдут проверку.

Исходные загрузки не сохраняются, но история анализа содержит **обезличенные снимки** текста, адреса и объяснений. Поздняя правка реестра не удаляет такой исторический снимок. Полнота автоматического маскирования не гарантируется ни для текущих записей, ни для снимков.

Нормализация адресов ограничена правилами и словарями; неизвестный адрес остаётся неизвестным. Геокодирования и официального адресного справочника нет. Метка языка определяется простой эвристикой, а не измерением качества NLP. TF-IDF не заменяет полноценную семантическую модель; E5, словари и пороги требуют проверки на размеченной русской и казахской выборке. Высокое сходство само по себе не доказывает общую аварию.

Ручное изменение групп и версии сводок реализованы. Следующие задачи: оценка NLP на реальном размеченном корпусе, авторизация и подготовка к многопользовательской работе. Утверждение локальным демо-оператором не является официальной подписью организации. P2 — карты, тёмная тема и несколько организаций — вне текущей работы. Дополнительно: [архитектура](docs/ARCHITECTURE.md), [AI-движок](docs/AI-ENGINE.md), [план](docs/PLAN.md), [полное продуктовое ТЗ](docs/SPECIFICATION.md).
