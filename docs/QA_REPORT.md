## Найденные ошибки и исправления

### QA-01 — подтверждённая проблема сохраняла отклонённый случай

**Было FAIL, после исправления PASS.** После подтверждения повторяющейся проблемы отклонение дочернего случая оставляло родителя подтверждённым. Такой статус мог попасть в новую сводку.

Исправление: изменение решения по случаю возвращает связанные активные проблемы на проверку, увеличивает их версию и пишет `related_review` с состояниями до/после. Связи и обращения сохраняются. Подтверждение проблемы с непустым отклонённым случаем отклоняется с HTTP 409. Черновик с прежним состоянием нельзя утвердить.

Метод: регрессионный API-тест сначала воспроизвёл ошибку; после правки группа тестов ручных решений и workspace прошла: **14 passed, 3 deselected**. Итоговый pytest также PASS.

### QA-02 — недопустимые символы могли ломать XLSX

**Было FAIL, после исправления PASS.** API ручных правок принимал NUL, vertical tab и недопустимый XML-символ U+FFFF. Эти значения несовместимы с корректным XLSX/XML.

Исправление: единая проверка строковых полей запросов до сохранения; такие символы возвращают 422 без отражения исходного ввода. CSV-проверка также отклоняет несовместимые символы. Обычные переводы строк и табуляция остаются допустимыми; защита от формул при экспорте сохранена.

Метод: три параметризованных регрессии сначала получили неожиданный 200; после исправления проверены сводка, название группы, текст обращения, неизменность данных и XLSX. Смежный набор: **55 passed**; итоговый pytest PASS.

### QA-03 — ложное обнаружение банковского счёта в слове «пересчёта»

**Было FAIL в браузере, после исправления PASS.** Обычный комментарий «…для проверки пересчёта и сохранения связей» возвращал 422: правило реквизитов совпадало с серединой слова.

Исправление: граница слова перед метками документов/счёта. Тот же комментарий повторно отправлен через UI, исключение успешно сохранено. Дополнительный тест проверяет обычный комментарий и сохранность маскирования синтетических `счёт`, `IBAN`, `паспорт`.

Метод: браузер + API + тесты приватности, ручных правок и безопасности: **30 passed**. Затем полный pytest: **123 passed**.

## AI: фактический метод и контроли

**PASS — модель действительно запустилась:** `intfloat/multilingual-e5-small`, ревизия `614241f622f53c4eeff9890bdc4f31cfecc418b3`, локальный CPU. Сходство — нормированные embeddings; классификация — прототипы E5 совместно с ограниченными RU/KK-правилами. Оба входа симметричного сходства получают `query:`. Это подтверждено новым live run и независимыми запусками, а не наличием файлов. После перезапуска сервер может снова показывать «загрузка не проверена» до первого вычисления в новом процессе; метод исторического завершённого запуска сохраняется.

**PASS — отсутствие модели:** реальный отсутствующий путь к весам и отдельный имитированный сбой модели приводят к завершённому анализу `tfidf_char`, `semantic=false`, с причиной перехода. Символьные n-граммы 3–5 и RU/KK-нормализация — резервный лексический метод, не полноценная семантическая модель.

Контроли A–I выполнены `scripts/qa_ai_controls.py` отдельно для E5 и TF-IDF: **9/9 PASS для каждого метода**. Каждый контроль проходит CSV → импорт API → отдельная SQLite → анализ → реальные evidence ID → повтор анализа → новое приложение с той же SQLite. Ожидаемый и полученный результат сохранены в `qa-ai-e5.json` и `qa-ai-tfidf.json` рядом с отчётом.

- **B PASS:** русский + казахский, один адрес: ожидался 1 случай из 2 ID, получен 1.
- **C PASS:** одна тема, разные адреса: ожидались 2 раздельных случая, получены 2.
- **D PASS:** один адрес, разные категории: ожидались 2 случая и 2 категории, получены 2 и 2.
- **E PASS:** один адрес/тема, интервал месяц: ожидались 2 случая и 1 повторяющаяся проблема, получены 2 и 1.

- **I PASS:** смешанный русский/казахский текст: ожидались водоснабжение и общий случай из 2 ID, получены оба результата.

**PASS — защита от цепочек слабого сходства:** отдельные pytest проверяют каждую пару и общий диапазон времени, широкие территории, отрицание события, перепубликацию через месяц и предел 90 дней. Ограничение: правила и пороги всё равно могут ошибаться.

**FAIL — точное восстановление всех эталонных групп большого демонабора.** Повторная оценка 176 допустимых записей из набора 180 строк в новом live run: эталон 23 случая, получено 34; 737 верно объединённых пар, 14 лишних объединений, 475 пропущенных связей. Мелкие контроли A–I не отменяют эту ошибку. Нельзя утверждать высокую точность или автоматически утверждать все группы. Сценарий сознательно включает ручную проверку и исключение ошибочного свидетельства `SYN-021`.

**NOT TESTED — качество на репрезентативной размеченной выборке реальных обращений.** Такой выборки нет. Геокодирование, точность установления единого происшествия и независимость авторов не заявляются. Метка языка — эвристика, смешанный текст может отображаться как «Қазақша».

Ограничение: ранее сохранённые обезличенные снимки остаются в истории; последующая правка записи не стирает их автоматически, а маскирование не идеально.
- **PASS — базовые границы ввода.** Проверены origin/host guard, SQL-параметризация и буквальный поиск `%`, `_`, кавычек, запрет некорректных символов, лимиты тела и файлов, optimistic locking, защита CSV/XLSX от формул. React выводит текст без `dangerouslySetInnerHTML`. Ограничение: полноценный penetration test и браузерный XSS-fuzzing не проводились.
- **FAIL — npm audit всех зависимостей.** Актуальный online audit: 5 high в dev-цепочке `eslint-config-next → @next/eslint-plugin-next → fast-glob → micromatch → braces`, [GHSA-vfj7-8cjw-p6xm](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm), переполнение стека на глубоко вложенных glob-шаблонах. `npm view braces version` вернул 3.0.3, исправленного выпуска в реестре на момент проверки нет. Предложенный npm downgrade eslint-config-next до 14.2.35 несовместим с выбранным поколением Next.js и не применён. Непроверенные glob-шаблоны не принимаются пользовательским API.
- **PASS — npm audit production-зависимостей:** `npm audit --omit=dev --json` вернул 0 известных уязвимостей. Ограничение: только данные реестра на момент проверки, не гарантия безопасности.
- **NOT TESTED — полный поиск CVE Python-пакетов**, нагрузочное/многопользовательское тестирование, утечки на уровне ОС, резервное восстановление на другом компьютере, чистая установка Windows, настольный Excel и публичное развёртывание.
- **FAIL для публичного применения — нет авторизации и ролей.** Локальный origin/host guard не заменяет authentication. Прототип предназначен для одного демо-оператора и синтетических данных на loopback; публичная эксплуатация и реальные обращения требуют отдельной защиты.

## Сбои проверки, не скрытые итоговым PASS

Четыре новых регрессионных теста сначала падали (QA-01 и три варианта QA-02). QA-03 воспроизведён настоящей кнопкой UI с HTTP 422; после правки та же операция прошла. Логи baseline, регрессий и итогового pytest сохранены в XML артефактах аудита.

Первый вариант сетевого запрета в контрольном скрипте блокировал служебный loopback socketpair Windows asyncio; исправлен сам тестовый стенд, разрешив только loopback. Это не внешний вызов AI. Один запрос npm audit оборвался `ECONNRESET`; повторный online audit из frontend завершился, его результаты приведены выше. Offline audit без актуальных данных не использован как доказательство отсутствия уязвимостей.

Браузерный file chooser сначала вернул timeout, затем выбор файла прошёл клавиатурой. Получение пути скачанного CSV также задержалось в инструменте; итоговый файл физически найден и проверен. Не каждый промежуточный timeout означал ошибку приложения.

## Воспроизведение и оставшиеся ограничения

Точные команды PowerShell для этой машины, dev/production и проверок находятся в [README.md](../README.md). Итоговые машинные свидетельства: [QA_VERIFICATION.json](QA_VERIFICATION.json), [контроли E5](qa-ai-e5.json), [контроли TF-IDF](qa-ai-tfidf.json).

К демонстрации готов основной путь: импорт → SQLite → локальный AI → проверяемая группа → ручное решение → утверждённая сводка → CSV/XLSX. Обязательна ручная оценка групп. Остались ошибки NLP на большом эталоне, dev-зависимость с advisory, неполное эвристическое обезличивание, отсутствие авторизации, предел 500 обращений и отсутствие автоматического переноса ручного состава при повторном анализе. Новые декоративные функции и новая архитектура не добавлялись.
