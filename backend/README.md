# Backend «Голос района»

Python 3.12, FastAPI, SQLAlchemy, SQLite, pandas, openpyxl и scikit-learn. Импорт, маскирование и реестр дополнены локальным анализом, историей результатов, ручной проверкой и редактированием групп, утверждаемыми сводками и экспортом CSV/XLSX. Основные команды всего проекта — в [корневом README](../README.md), правила алгоритмов — в [docs/AI-ENGINE.md](../docs/AI-ENGINE.md).

## Установка и запуск

Из каталога `backend` в PowerShell:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-lock.txt
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --no-access-log
```

Активация venv не требуется. При обновлении используйте имеющееся окружение и повторите установку зависимостей; база остаётся прежней.

Доступны [API-документация](http://127.0.0.1:8000/docs) и [health](http://127.0.0.1:8000/api/health). Запускайте один процесс/worker backend: согласование нескольких процессов и распределённая очередь не реализованы.

Проверки:

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m pip check
```

Тесты используют отдельные временные базы. Фактические результаты текущей проверки — в [QA_REPORT](../docs/QA_REPORT.md).

### Необязательная модель

Базовых зависимостей достаточно для TF-IDF. Для E5, из каталога `backend`:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-ai.txt
.\.venv\Scripts\python.exe ..\scripts\download_model.py
```

Загрузчик сохраняет `intfloat/multilingual-e5-small` в `backend/models/multilingual-e5-small`. Другой локальный каталог задаётся загрузчику через `--output`, а backend — через `DISTRICT_VOICE_MODEL_PATH`. Установка и загрузка требуют сети; анализ — нет. После установки перезапустите процесс, поскольку модель кешируется в памяти.

Автоматический анализ не скачивает модель: только локальные файлы, `local_files_only=True`, `trust_remote_code=False`, CPU. В `auto` ошибка или отсутствие E5 приводит к резервному TF-IDF с сохранённой причиной; `tfidf` выбирает его явно. `GET /api/analysis/status` проверяет доступность файлов, но не подтверждает успешную загрузку E5. Фактический метод берите из завершённого `AnalysisRun`.

## Хранение и контракт импорта

- База находится в `backend/data/district_voice.db`, независимо от рабочего каталога. Для отдельной базы задайте `DISTRICT_VOICE_DATABASE_URL=sqlite:///C:/path/to/test.db`; родительский каталог должен существовать.
- `POST /api/imports/preview`: multipart `file`, необязательное поле `mapping` — JSON-объект с ключами `source`, `source_record_id`, `date`, `text`, `address`, `official_status` и значениями названий столбцов. Ответ содержит маскированные строки, ошибки, предполагаемые дубли/конфликты и `preview_id`.
- `POST /api/imports/confirm`: `{ "preview_id": "..." }`. Сохраняет пригодные строки, возвращает независимые счётчики `accepted`, `rejected`, `duplicates`, `conflicts`. Повтор для того же предпросмотра возвращает ту же партию.
- `GET /api/appeals`: поиск `q` без учёта регистра, фильтр `privacy_status`, `page`, `page_size` (1–100). Поиск работает по обезличенным тексту, адресу, источнику и ID.
- `PATCH /api/appeals/{id}/privacy`: `{ "text": "...", "address": "...", "version": 1 }`. Оператор подтверждает ручную проверку. Новые распознаваемые персональные сведения отклоняются; устаревшая версия даёт 409. Журнал содержит время, версии, статус и хеши текста. Личность оператора не аутентифицируется: используется `local_operator`. Правка помечает запись ожидающей нового анализа.
- `GET /api/imports` — история партий; `GET /api/stats` — расчёт чисел из сохранённых обращений. `masked` и `review_required` считают текущие статусы, а не качество обезличивания. `by_territory` группирует исходное безопасное поле адреса, а не нормализованную территорию отдельного запуска анализа.
- `create_app(database_url=...)` позволяет запускать тесты на отдельной SQLite; `app.state.session_factory` и `app.state.engine` доступны для тестовых сценариев.

## Правила импорта

CSV: UTF-8/BOM либо Windows-1251; разделители — запятая, точка с запятой или табуляция. XLSX: первый лист. Максимум 5 МБ, 5000 обращений и 60 столбцов. Для XLSX диапазон листа не должен превышать 5001 строку вместе с заголовком. Формулы, макросы и подозрительно сжатые XLSX отклоняются. Неизвестные обязательные столбцы сопоставляются вручную.

Обязательны источник, ID, дата и текст. Поддерживаются `ГГГГ-ММ-ДД`, `ДД.ММ.ГГГГ`, `ДД/ММ/ГГГГ`, `ГГГГ/ММ/ДД` и ISO datetime. Пустой адрес или статус становятся «неизвестно». Текст — до 20000 символов; источник и статус — до 120, ID — до 160, адрес — до 500. Непригодная строка не блокирует остальные. Номера ошибок соответствуют строкам исходного файла; у CSV с переносами внутри ячейки — начальной физической строке записи.

Техническая уникальность — точное сочетание `source + source_record_id` после удаления пробелов по краям. Совпадение SHA-256 всех нормализованных исходных полей — дубль, другое содержимое при том же ключе — конфликт. Похожий текст с другим ID сохраняется отдельно. Повторный импорт после ручной правки не перезаписывает решение оператора.

Предпросмотр действует 24 часа; просроченные неподтверждённые записи удаляются при следующем предпросмотре. Подтверждённые предпросмотры сохраняют ID партии для идемпотентности, но список строк очищается. `valid_rows` — все строки без ошибок, включая возможные дубли и конфликты; это не количество будущих новых обращений. При подтверждении дубли проверяются повторно в транзакции.

## Анализ и API

`app/ai/engine.py` принимает уже обезличенные записи и не обращается к базе. `analysis_api.py` получает текущие записи, выполняет расчёт, проверяет результат и сохраняет его. Модель и резервный алгоритм описаны в [AI-ENGINE](../docs/AI-ENGINE.md), включая словари, пороги, временные интервалы и ограничения нормализации адресов.

- `GET /api/analysis/status` — прогноз доступного метода, последний запуск, категории и количество записей. `model_load_verified=False` означает, что загрузка модели этим запросом не подтверждена.
- `POST /api/analysis/run` с `{ "mode": "auto" }` или `{ "mode": "tfidf" }` — синхронный запуск на текущем наборе. Возвращает сохранённый объект запуска; статус завершения `completed` либо `failed`.
- `POST /api/analysis/runs/{id}/retry` — новый запуск с текущими обращениями и ручными категориями. Поле `rerun_of` связывает его с предыдущим; JSON `mode` необязателен.
- `GET /api/analysis/runs`, `GET /api/analysis/runs/{id}` — история, фактический метод, время, счётчики, безопасные ошибки и `stale`.
- `GET /api/analysis/results?run_id=...` — результаты и безопасный снимок обращения: категории, метод, `score`, неопределённости, территория, признаки перепубликации, объяснения, статус и версии. Без `run_id` выбирается последний успешно завершённый запуск.
- `GET /api/groups?run_id=...&kind=case` либо `kind=problem` — предложения локальных случаев или повторяющихся проблем. Новые предложения имеют статус `proposed`; ручная проверка сохраняет `confirmed` или `rejected`. Архивные группы после разделения/объединения не входят в активный список.
- `GET /api/problems/{id}` — проблема и связанные `case_ids`; `GET /api/groups/{id}/appeals` — текущие безопасные поля записей и вложенный исторический `analysis` для сверки доказательств.
- `GET /api/analysis/issues?run_id=...` — блокировки приватности, неопределённости, ошибки и устаревание.
- `PATCH /api/appeals/{id}/category` с `{ "category": "Дороги", "version": 1, "reason": "Сверено с текстом" }` — ручная категория и журнал решения. Категория должна входить в справочник, причина — 3–500 символов. Устаревшая версия даёт 409. После сохранения требуется повторный анализ.

**Версии различаются:** `input_version` — версия текста/адреса на момент расчёта; `version` в результате анализа — токен версии ручной категории для PATCH. В доказательствах `appeal_version` — текущая версия самого обращения. Историческая `category` не переписывается после правки: текущая ручная категория возвращается как `override_category`, необходимость пересчёта — как `requires_reanalysis`.

`score` — оценка метода, не вероятность. `message_count` включает сообщения, `source_count` — разные значения источника, `independent_evidence_count` оценивает публикации без предполагаемых повторов; это не число уникальных жителей или доказанно независимых авторов. Одиночные случаи тоже входят в `case_count`.

## Ручная проверка и сводки

`workspace_api.py` предоставляет dashboard, расширенный реестр, проверку статуса группы и рабочие JSON-отчёты. `group_actions.py` реализует правку названия/категории, добавление/исключение обращений, разделение и объединение групп. Изменения пересчитывают состав, период, источники и связи, сохраняют историю демо-оператора и помечают старое AI-объяснение устаревшим. Исходные обращения не удаляются. Версии защищают от перезаписи чужих изменений.

`summary_api.py` рассчитывает показатели по периоду и территории, сохраняет черновик и правки текста, утверждает снимок и экспортирует CSV/XLSX. Утверждённая версия защищена от изменения и удаления триггерами SQLite; последующая правка групп не меняет её числа. Новые изменения оформляются новой версией. Контракты и ограничения — в [MVP-COMPLETION](../docs/MVP-COMPLETION.md); актуальные схемы запросов — в локальной `/docs`.

## Согласованность и обновление SQLite

Модуль анализа добавляет таблицы `analysis_runs`, `appeal_analyses`, `analysis_groups`, `analysis_group_memberships`, `analysis_problem_cases`, `category_overrides`, `category_audit`. Они регистрируются до `Base.metadata.create_all`; схема существующей таблицы `appeals` не меняется. Старые обращения, партии и журналы сохраняются. Удаление базы или повторный импорт не требуются. Ручные решения и сводки используют дополнительные таблицы журналов и `summaries`. Это добавление новых таблиц, а не универсальный механизм будущих миграций.

Каждый запуск сохраняет состав и версии входных записей и ручных категорий. Расчёт выполняется вне транзакции записи. Перед сохранением состав и версии проверяются повторно: изменение набора во время расчёта даёт `failed`/`stale`, без публикации частичных групп. Предыдущие успешные результаты остаются доступными.

Допускается один анализ одновременно; второй получает 409. Один запуск обрабатывает максимум 500 сохранённых обращений. При превышении возвращается 422, без молчаливого усечения. Прерванные остановкой процесса запуски при следующем старте отмечаются как `failed`, после чего их можно повторить. Несколько backend workers не поддерживаются.

## Приватность и ограничения

Сырые файлы и тексты не сохраняются приложением на диск; для сравнения импорта хранится SHA-256. В БД и API используются результаты маскирования. Скрываются распознаваемые телефоны, email, 12-значные ИИН/ЖСН; ФИО, квартира и документы дают дополнительный признак проверки. Риск личных сведений в источнике, ID или официальном статусе отклоняет строку. Поэтому 12-значный ID нужно заменить допустимым неперсональным идентификатором.

Поток загрузки ограничен 5 МБ плюс служебные поля multipart; порог временного файла выше лимита, поэтому принятые файлы обрабатываются в памяти и закрываются после чтения. Правила не гарантируют полного обезличивания. `clear` означает отсутствие найденных правилом признаков либо ручную проверку, а не доказательство отсутствия личных сведений.

Перед анализом маскирование проверяется повторно. Записи `review_required` и записи с вновь обнаруженными персональными сведениями получают `blocked` и не участвуют в embeddings или группировке. Метка языка `ru`/`kk` остаётся простой эвристикой; она не доказывает качество классификации.

Журнал правок приватности хранит хеши вместо предыдущих текстов. **История анализа отдельно сохраняет обезличенный снимок текста и адреса**, использованный в расчёте. Изменение текущего обращения не удаляет прежний снимок. В интерфейсе историческое доказательство и текущая версия обозначены отдельно.

Приложение однопользовательское, без авторизации и ролевой модели. Слушайте `127.0.0.1`; CORS и проверка Origin допускают только `localhost`/`127.0.0.1` на портах 3000 и 8000. Для публичного размещения этого недостаточно. Нет геокодирования и официальной проверки адресов. Ручные решения не переносятся автоматически в новый анализ; исторические обезличенные снимки сохраняются. Ограничения точности и результаты проверок описаны в [QA_REPORT](../docs/QA_REPORT.md).
