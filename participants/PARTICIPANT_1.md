# Участник 1

**Проект:** Голос района. **Зона ответственности:** Импорт, хранение и сервер.

Это инструкция для сменяемой роли. При передаче обязанностей не менять номер под имя человека: заполнить [передачу работы](../docs/HANDOFF.md).

## Цель
Надёжно загрузить обращения, разделить доступ и обеспечить воспроизводимые числа в аналитике.

## Обязательный контекст
Прочитать [ТЗ](../docs/SPECIFICATION.md), [план](../docs/PLAN.md) и [правила команды](../docs/TEAMWORK.md). В ТЗ находятся общий сценарий, поля, статусы, ограничения MVP, риски и вопросы заказчику.

## Конкретные задачи
1. В день 1 согласовать единственный шаблон Excel/CSV, справочники и контракт с двумя участниками.
2. Сделать предпросмотр, сопоставление столбцов, проверку дат/полей и отчёт об ошибочных строках.
3. Хранить источник, ID в источнике, дату, текст, адрес/район и исходный официальный статус отдельно от анализа.
4. Защитить от повторного импорта по источнику/ID; конфликт содержимого не перезаписывать молча.
5. Разделить оригинальные данные и допустимое обезличенное представление; настроить серверные права.
6. Подключить модуль обезличивания Участника 2 до любых внешних AI-вызовов; сомнительные записи останавливать на проверку.
7. Сделать партии анализа со статусами, ошибками и повторным запуском без новых обращений.
8. Сохранять классификацию, группы, случаи, проблемы, решения аналитика и журнал.
9. Рассчитывать числа сводки программно, фиксировать период и состав источников; не считать сообщения уникальными жителями.
10. Сохранять версии утверждённых сводок и API для экспорта; экспортный интерфейс/файл принадлежит Участнику 3.

## Что получить от команды
От Участника 2: безопасная запись, аналитическая схема и модуль обезличивания. От Участника 3: требования экранов и пользовательские решения.

## Что передать команде
Импорт; база/права; API анализа и решений; агрегаты; версии сводок; продуктовые метрики; общий запуск.

## План по дням
- **День 1:** Шаблон, контракт, схема, предпросмотр и правила дублей; показать импорт в интерфейсе.
- **День 2:** Права, безопасная обработка, API реестра и повторный запуск.
- **День 3:** Сохранение групп/решений и вычисляемые агрегаты.
- **День 4:** Версии сводки, журнал, измерение времени и общая приёмка.

## Критерии приёмки
- [ ] Повторный импорт не увеличивает статистику.
- [ ] Каждая отклонённая строка имеет объяснение.
- [ ] Оригинал не попадает в API аналитика/руководителя или внешнего AI.
- [ ] Числа утверждённой версии воспроизводимы из сохранённого набора данных.
- [ ] Изменения совместимы с согласованным контрактом.
- [ ] Остальные участники могут запустить и проверить результат по переданной инструкции.
- [ ] Известные ограничения и незавершённые задачи записаны.
- [ ] Демонстрационные данные и неготовые возможности обозначены явно.

## При смене роли
Зафиксировать текущую ветку/коммит, запуск, результат проверок, незавершённые задачи и следующий шаг в [HANDOFF.md](../docs/HANDOFF.md). Получающий роль проверяет запуск и продолжает по этому файлу. Обсуждения и изменения контракта сохранять в репозитории, чтобы знания не оставались только у одного человека.
